# Pure Dart NOOA Architecture Guidelines & Invariants

This rule set defines the architectural invariants for `mobi_nooa_core` and pure Dart agent subsystems.

---

## 🏛️ Core Principles & Invariants

1. **Zero Flutter Dependency in `mobi_nooa_core`**:
   - `mobi_nooa_core` must remain platform-agnostic and runnable in pure Dart, server-side, or headless embedded Android contexts. Never import `package:flutter` or `dart:ui` into `mobi_nooa_core`.
2. **Pass-by-Reference Object Heap (NOOA Principle 2)**:
   - Never return large objects (datasets, logs, large strings) directly in tool returns.
   - Wrap them via `ObjectHeap.maybeWrap(data)` so the LLM receives an isolated handle (`#ref_xxx`) and bounded preview.
3. **Explicit State Isolation (NOOA Principle 5)**:
   - State reasoning by LLMs must flow through `NooaAgent.getState(key)` and `NooaAgent.setState(key, value)` rather than private instance variables.
4. **CodeAct Pre-Execution AST Validation (NOOA Principle 3)**:
   - Every executable code snippet generated by an LLM must pass through `AstGuardrails.validate()` before reaching `CodeActEngine` or `SandboxedEnvironment`.
5. **Owner-Gated Cognitive Memory**:
   - In multi-agent or subagent execution, long-term memory accesses must be wrapped in `OwnerGatedMemoryScope` to prevent cross-agent memory contamination.
6. **Tiered Permission Policies**:
   - Dangerous mutating actions (filesystem writes, shell executions, device notifications) must be gated by `PermissionManager.authorize()` and support interactive `ApprovalCallback`s.
7. **Append-Only Session Logging & Time-Travel**:
   - Append meaningful events to `SessionEventLog` for compliance, time-travel replay (`sessionLog.replay(step)`), and immutable branch forking (`sessionLog.fork(...)`).
